## Direction findings surfaced but not selected (available for future planning)

From the 2026-08-28 direction audit; the maintainer chose project-scoped
configuration first. These remain open options, not rejections:

- **Distribution & shell ergonomics** — Homebrew tap, crates.io publication,
  shell completions (`clap_complete` absent from `Cargo.toml`); install is
  currently script-or-manual only (README install section).
- **Read-only / capability-gated mode** — README's threat-model section
  documents that any caller can rewrite injection topology via write
  commands; no gating exists in `src/`.
- **`run --pure` environment isolation** — `src/runner.rs:135-142` passes the
  full inherited environment to the target; an opt-in declared-plus-minimal
  base would prevent stray parent-shell secrets from reaching launched
  processes.
- **Audit trail for credential use** — v1 design doc §10 permits logging
  credential name/provider/time/target; no such log exists.
- **MCP server surface** — read-only exposure (list/show/get/find, credential
  status) for MCP-only agent hosts; skill and AGENTS.md block cover the rest.

## Findings considered and rejected

- **Native providers for 1Password/Vault/Doppler etc.**: the `command`
  provider already delegates to any external manager without a shell
  (README's `op read` example); native integrations would duplicate it for
  marginal UX. Revisit only on concrete user demand.
- **Cloud sync, GUI, auto-guessing missing fields**: recorded non-goals in
  the v1 PRD (`.sdd/changes/archive/2026-08-22-001-agent-context-cli/prd.md`
  lines 23–26); not re-proposed.
